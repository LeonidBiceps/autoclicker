# Публикация

Аккаунт пока не нужен — весь код работает на моке. Этот документ описывает, что
делать, когда аккаунт появится.

> Точные лимиты (вес архива, форматы обложек, правила модерации) платформа
> периодически меняет. Здесь описан порядок действий; конкретные цифры сверяйте
> с актуальной документацией в консоли разработчика.

## 1. Аккаунт

Консоль разработчика — `games.yandex.ru/console`. Нужен обычный аккаунт
Яндекса; отдельной регистрации студии не требуется. Для выплат позже
понадобится привязать способ получения дохода — это делается в настройках
консоли и не блокирует публикацию черновика.

## 2. Черновик

Создайте черновик игры и заполните карточку:

- **Название и описание.** Первые два предложения описания видны в каталоге —
  туда идёт суть механики, а не история студии.
- **Категории и теги.** Влияют на то, в каких подборках игра появится.
- **Возрастной рейтинг.** Занижать нельзя: это частая причина отказа модерации.
- **Языки.** Если игра на русском — укажите только русский, иначе она попадёт в
  выдачу для аудитории, которая её не поймёт, и утянет вниз показатели.
- **Обложки и скриншоты.** Готовятся отдельно; это единственная часть, которую
  каркас за вас не сделает.

## 3. Загрузка сборки

```bash
npm run package -- merge2048
```

Архив появится в `build/merge2048-v0.1.0.zip`. Он уже проверен на то, что чаще
всего ломает публикацию:

- `index.html` лежит в корне архива, а не во вложенной папке;
- нет ссылок на внешние домены — всё, кроме самого SDK Яндекса, внутри;
- нет абсолютных путей (`/assets/...`), которые ломаются на CDN;
- вес в пределах бюджета.

Если проверка не прошла, `npm run package` откажется собирать архив и назовёт
причину.

## 4. Лидерборд

**Это самый частый источник «у меня всё сломалось после публикации».**

Игра обращается к лидерборду по техническому имени — константа `LEADERBOARD` в
`src/main.ts` каждой игры. Имя должно состоять только из латинских букв и цифр,
без подчёркиваний и других символов — иначе консоль откажется его принять.
Актуальные имена по играм:

| Игра | Технический код | Имя лидерборда |
| --- | --- | --- |
| merge2048 | `merge2048` | `bestScore` |
| gems | `gems` | `bestScore` |
| astroassault | `astroassault` | `bestWave` |
| starfarm | `starfarm` | `lifetimeEnergy` |
| lovestory | `lovestory` | `totalHearts` |
| towerstack | `towerstack` | `bestHeight` |

В консоли нужно создать лидерборд **с тем же техническим именем**, иначе вызовы
молча не сработают: обёртка гасит ошибку, чтобы не ронять игру, и в интерфейсе
просто окажется пустая таблица. Порядок сортировки — по убыванию, тип значения —
целое число.

## 5. Проверка на реальной платформе

У черновика есть ссылка для тестирования. Откройте игру по ней и убедитесь, что:

- прелоадер снимается (значит, `LoadingAPI.ready()` дошёл);
- rewarded-реклама доходит до награды, а не закрывается на середине;
- после просмотра рекламы вернулся звук и не «залип» игровой цикл;
- сейв переживает перезагрузку страницы;
- результат появляется в таблице лидеров после входа в аккаунт.

Полноэкранная реклама на черновике может не показываться — это нормально,
рекламные блоки включаются не сразу.

Чтобы проверить поведение **без** мока локально, добавьте к адресу дев-сервера
`?mock=0`: обёртка попробует загрузить настоящий SDK и, не найдя его, уйдёт в
режим «платформы нет». Игра при этом обязана остаться играбельной.

## 6. Модерация

После отправки игра уходит на проверку. Типовые причины отказа: заниженный
возрастной рейтинг, реклама в первые секунды сессии, неработающие кнопки,
отсутствие реакции на закрытие рекламы. Первые две в каркасе учтены —
полноэкранная реклама не покажется в первые 45 секунд сессии и чаще одного раза
в ~70 секунд.

## 7. После публикации

Подключите счётчик Яндекс.Метрики и передайте его id в
`metrics.attachYandexMetrica(...)` — воронка уже размечена событиями
(`load_done`, `game_start`, `game_over`, `ad_rewarded_shown`, `shortcut_accepted`
и другие). Без этих данных решать, что делать со следующей игрой, придётся
вслепую.
