# Clash Royale Tracker — отдельный проект

Счётчик эликсира и открытой колоды противника в Clash Royale (через эмулятор на ПК), вынесенный из
`desktop-clicker` (МультиТул) в отдельный проект. Причина переноса — не организационная, а
техническая: см. «Почему не в МультиТуле» ниже.

**Это новый проект, начатый с нуля в этой папке.** Код, который раньше жил в `desktop-clicker`
(`clash-*.js`, `renderer/clash-*.html`), был полностью удалён оттуда — здесь не переиспользуется,
пишется заново, с другой архитектурой распознавания. Единственное, что перенесено, — маленький
сид-датасет реальных скриншотов, см. `data/seed-samples/`.

## Почему не в МультиТуле — что уже проверено и почему сравнение пикселей не работает

В `desktop-clicker` распознавание шло сравнением сырых пикселей кропа (motion-detection на
изменившихся клетках поля) с сохранёнными образцами. Проверено вживую на настоящих скриншотах:

- Два РАЗНЫХ снимка ОДНОЙ и той же карты дают корреляцию ~0.55-0.6.
- Два снимка РАЗНЫХ карт (без общего фона, специально подобранные для честного сравнения) дают
  ~0.4-0.42.

Разрыв есть, но маленький — сравнение по сырым пикселям (даже с маскировкой фона по краю кропа)
не устойчиво к смене ракурса/позы/анимации юнита. Изучил, как эту же задачу решают серьёзные
проекты:

- [cr-bot](https://github.com/Keschler/cr-bot) — детекция через "патченый KataCR dual-YOLO
  runtime", классификация карт руки через MobileNetV3-Small.
- [KataCR](https://github.com/wty-yy/KataCR) — связка YOLOv8-детекторов (комбинация нескольких,
  т.к. 150 категорий разного размера) + классификаторы, обучено на собственном размеченном
  датасете ([Clash-Royale-Detection-Dataset](https://github.com/wty-yy/Clash-Royale-Detection-Dataset)).

Вывод: серьёзная точность требует ОБУЧЕННУЮ модель, не сравнение картинок. Это другой стек —
поэтому отдельный проект, а не доработка `desktop-clicker`.

## Честно про ограничения этой среды — до старта работы

- **Нет GPU и пайплайна обучения в этой рабочей среде.** Обучить YOLO-детектор с нуля здесь
  нельзя. Реалистичный путь — **инференс на CPU** через [ONNX Runtime for
  Node](https://www.npmjs.com/package/onnxruntime-node) (нативный аддон, ставится как обычная
  npm-зависимость, не требует Python) с УЖЕ обученной моделью, плюс лёгкий классификатор поверх
  (например, k-NN/логрег над эмбеддингами), который можно дообучать на CPU на своих же данных.
- **Обучающих данных почти нет.** `data/seed-samples/` — 14 картинок на 10 карт (1-3 штуки на
  карту), перенесённые из `desktop-clicker` (это СВОИ скриншоты из игры, не скачанные откуда-то —
  тот же принцип "не встраиваем графику Supercell", что действовал в `desktop-clicker`). Для
  честного обучения нужны сотни-тысячи размеченных примеров на карту. Готовые датасеты
  (`Clash-Royale-Detection-Dataset` и т.п.) построены на скриншотах игры — использовать их
  напрямую можно только если это устраивает с точки зрения происхождения данных; это решение
  пользователя, не техническое.
- **Лицензия/происхождение любой готовой предобученной модели** для этой игры тоже стоит проверить
  перед использованием — она почти наверняка обучена на чужих скриншотах игры.

## Реалистичный план (черновой, для обсуждения в новой сессии)

1. Определиться с источником модели/данных: (a) собирать свой датасет вручную/полуавтоматически
   дольше, но чисто по происхождению; (b) использовать сторонний датасет/модель — быстрее, но с
   вопросом происхождения данных, который решает пользователь.
2. Настроить CPU-инференс (ONNX Runtime for Node) в Electron или отдельном Node-процессе —
   независимо от источника модели, это техническая база.
3. Определиться с архитектурой: полноценная детекция (YOLO — находит юнита НА поле, где угодно) vs
   классификация уже вырезанной области (проще, но требует свою логику "где вырезать" — как раз то,
   что уже частично сделано в удалённом коде: сетка + motion-detection для поиска "где что-то
   изменилось", только дальше не сравнение пикселей, а прогон через модель).
4. Отдельное приложение: скорее всего свой Electron-проект (переиспользовать nut-js для захвата
   экрана — та же библиотека, что в `desktop-clicker`), не встраивать обратно в МультиТул.

## Начинать здесь стоит с новой сессии/чата

Этот README написан так, чтобы новая сессия Claude Code, открытая в этой папке, могла продолжить
без потери контекста — не нужно пересказывать историю разработки в `desktop-clicker`.
