# WB — Позиции в поиске

Инструмент для продавцов Wildberries: отслеживает позицию твоих товаров в органической выдаче
поиска по своим ключевым словам, с историей изменений по датам. MVP — первая полезная функция,
дальше можно наращивать (юнит-экономика, отслеживание конкурентов и т.п.).

## Как это работает

1. **Добавить товар** — зайди на страницу своего товара на `wildberries.ru`
   (`.../catalog/<nmId>/detail.aspx`) и открой иконку расширения: оно само прочитает артикул и
   название со страницы, останется только вписать ключевое слово и нажать «Добавить в
   отслеживание». Ручной ввод артикула не нужен.
2. **Проверить позицию** — зайди на `wildberries.ru`, введи в поиск ровно тот запрос, что указал
   как ключевое слово. Расширение само сканирует загруженную выдачу и показывает позицию прямо на
   странице (плашка в правом верхнем углу) и в popup — и сохраняет её в историю.
3. Если товар не входит в первую подгруженную porцию — прокрути страницу вниз (Wildberries
   подгружает товары по мере скролла), расширение пересканирует автоматически.
4. **В любой другой момент** — просто открой иконку расширения: увидишь последнюю известную
   позицию по каждому товару, даже если ты сейчас не на Wildberries.
5. Полное управление (добавить ключевое слово к уже отслеживаемому товару, удалить товар,
   посмотреть полную историю) — на странице настроек (кнопка «Товары и история →» в popup).

## Как определяется органическая позиция (важно для доверия к цифрам)

Wildberries вставляет рекламные карусели прямо в общий список выдачи (`.product-card-list`), но
как **отдельные обёртки**, а не как товары верхнего уровня — проверено вживую: рекламные блоки
(на момент проверки — карусели вида «...» и подборки брендов) лежат в `.product-card-list`, но
сами не имеют класса `.product-card`, а уже ВНУТРИ себя содержат вложенные `.product-card`.
Поэтому расширение считает позицию только по **прямым потомкам** списка с классом `.product-card`
— это даёт органический рейтинг без рекламных вставок. Если Wildberries изменит вёрстку —
позиции перестанут находиться, а не станут тихо неправильными: `content.js` явно завязан на
`.product-card-list` + прямые `.product-card` потомки, при изменении разметки просто ничего не
найдётся (страница покажет плашку «не найден»), а не соврёт число.

## Как читается карточка товара (для быстрого добавления)

Артикул — из URL (`/catalog/<nmId>/detail.aspx`, стабильный формат много лет). Название — из
элемента `[class*="productTitle"]` на странице (проверено вживую на реальной карточке); если
Wildberries переверстает страницу и этот класс исчезнет — есть запасной вариант: заголовок
вкладки браузера (`document.title`) обрезается по слову «купить». В любом случае это происходит
только в момент, когда сам открываешь popup на странице товара (`activeTab` + `scripting`) — без
постоянного доступа к содержимому вкладок.

## Известные ограничения (MVP, не баги)

- **Постраничная навигация не поддерживается** — `?page=N` в URL не работает надёжно (это SPA с
  бесконечной прокруткой, обычная перезагрузка страницы сбрасывает на первую porцию). Чтобы
  проверить позицию 150+, нужно прокрутить страницу вниз до нужной глубины вручную, пока товар не
  подгрузится, а не просто открыть ссылку.
- **Требует открытую вкладку** — это не фоновый мониторинг 24/7 без твоего участия. Позиция
  фиксируется в истории только в моменты, когда ты сам открыл поиск по нужному запросу.
- **Точное совпадение ключевого слова** — сравнение регистронезависимое, но точное (без учёта
  опечаток/синонимов/перестановки слов). Введи в поиск ровно тот текст, что сохранил как ключевое
  слово.
- **История пишется не чаще раза в 6 часов** на одну и ту же комбинацию товар+запрос+позиция —
  чтобы скролл туда-сюда не заваливал историю дублями. Если позиция реально поменялась —
  запишется сразу, независимо от таймера.
