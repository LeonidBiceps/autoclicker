# native-clicker — нативный burst-цикл для турбо-режима

Rust + [napi-rs](https://napi.rs/) модуль: весь цикл кликов турбо-режима крутится здесь, в нативном
коде, напрямую через Windows `SendInput` — не в JS. Подробно зачем и что именно это ускоряет — см.
раздел про турбо-режим в [../README.md](../README.md).

## Почему не просто "более нативный клик"

`nativeMouse.click()` в `main.js` (голый биндинг nut-js) уже быстрый сам по себе — тут нечего
ускорять дальше. Узкое место у турбо-режима — JS/event-loop накладные расходы ВОКРУГ клика
(несколько `await` на тик, `setImmediate` для планирования следующего). Поэтому этот модуль не
просто ещё раз "кликает" — он крутит ВЕСЬ цикл (интервал, повтор, остановка) сам, и JS вызывается
только один раз на старте burst'а и один раз на остановке.

Измерено вживую (см. память проекта/README): относительно обычного JS-турбо стабильно быстрее на
~40-45% в одинаковых условиях — абсолютные цифры сильно шумят в зависимости от состояния системы
(Windows троттлит фоновые процессы), но относительный выигрыш воспроизводится стабильно.

## Сборка

```bash
cargo build --release
```

Дальше скопировать `target/release/native_clicker.dll` в `native-clicker.win32-x64-msvc.node`
(да, расширение `.node` — это просто DLL, Node грузит её через `require()` независимо от
расширения файла).

**Важная ловушка — Windows Defender Controlled Folder Access.** Если у тебя включена защита от
шифровальщиков (Controlled Folder Access, `Get-MpPreference` → `EnableControlledFolderAccess`) и
папка `Documents` в списке защищённых (по умолчанию так и есть) — `cargo build` тут же упадёт с
непонятной ошибкой `failed to write Cargo.lock: не удаётся найти указанный файл`, потому что
`cargo.exe`/`rustc.exe` не в списке разрешённых приложений и молча не может ничего записать в
Documents. Проверить: `Get-MpPreference | Select EnableControlledFolderAccess`. Решение — либо
добавить `cargo.exe`/`rustc.exe`/`link.exe` в разрешённые (Защитник Windows → Защита от
вирусов и угроз → Управление защитой от программ-шантажистов → Разрешить приложению доступ через
контролируемый доступ к папкам), либо (как сделано при первой сборке) собирать в папке ВНЕ
`Documents` (например, `%TEMP%`) и копировать оттуда только готовый `.node`-файл — сам компилятор
не единственное, что подвержено этому: любой процесс без доверия у Defender будет получать ту же
ошибку.

## Требования для сборки

- Rust (`rustup`, стабильный тулчейн `x86_64-pc-windows-msvc`)
- Visual Studio Build Tools (workload "Desktop development with C++" / `Microsoft.VisualStudio.Workload.VCTools`) — даёт `link.exe`, без него Rust на Windows с MSVC-таргетом не соберёт ничего с зависимостями (в т.ч. голый `cargo check` тоже требует линковщик, если у зависимостей есть build-скрипты — например, у `windows-sys`).

Дальнейшая пересборка (уже после первой настройки тулчейна) — просто `cargo build --release`,
занимает секунды.

```
Cargo.toml, Cargo.lock, build.rs, src/lib.rs   исходники — в git
native-clicker.win32-x64-msvc.node             СКОМПИЛИРОВАННЫЙ бинарник — тоже в git (не у всех,
                                                кто клонирует репозиторий, будет настроен Rust-тулчейн
                                                для пересборки; раз собранный .node работает везде
                                                благодаря ABI-стабильности N-API)
test.js                                        автономная проверка (без Electron) — крутит короткий
                                                burst и сверяет счётчик Rust с независимым наблюдением
                                                через uiohook-napi (тот же принцип, что и у записи
                                                макросов в приложении)
target/                                        артефакты сборки — в .gitignore, не коммитится
```

## Поддерживаемые случаи (см. `canUseNativeTurbo()` в `../main.js`)

Только простой спам-клик мышью: без разброса позиции, без триггеров (цвет/текст/картинка), без
привязки к окну, без последовательности точек, не двойной клик. Во всех остальных случаях
(что-то из перечисленного включено) турбо-режим тихо остаётся на обычном JS-цикле — разница
только в скорости, не в возможностях.
